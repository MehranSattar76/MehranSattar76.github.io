Privacy Policy for Ping Booster: Fix Game Lag

Effective Date: November 13, 2026  |  Developer: MZ Developers (Mehran Sattar)  |  Contact: support@mzdevelopers.com

🛡️ Our Core Privacy Commitment: Ping Booster operates on a strict local-first, on-device architecture. We do NOT operate remote proxy servers, we do NOT inspect or log user traffic, and we NEVER sell, monetize, or transmit your personal data or internet traffic to third parties.

1. Overview & Architectural Principles

This Privacy Policy outlines how Ping Booster: Fix Game Lag ("the Application", "we", "our", or "us"), developed and published by MZ Developers, handles data, device permissions, and network communications when you download and use the application on Android devices.

Ping Booster is engineered as a performance utility to reduce in-game network latency, benchmark DNS response times, diagnose Wi-Fi signal interference, and stabilize packet delivery for mobile multiplayer games.

2. On-Device VpnService Architecture & Zero Payload Inspection

Android requires applications that manage network sockets or packet routing to declare the VpnService API. We hold a strict standard regarding this capability:

  • 100% Local Loopback: The VPN interface initialized by Ping Booster is an on-device inverted split-tunnel loopback interface. All routing decisions are executed locally in memory on your physical Android device.
  • No External VPN Servers: Your internet traffic is never routed through remote external VPN tunnels, third-party proxies, or cloud relay servers.
  • Zero Payload or Packet Inspection: The application does not inspect, read, decrypt, parse, or log payload contents, URLs, DNS lookup records, login credentials, or game communications passing through network interfaces.
  • Traffic Prioritization Only: The loopback interface simply prioritizes packets belonging to your designated foreground game process over background non-essential applications to minimize bufferbloat and latency spikes.

3. Device Permissions & Technical Justifications

Ping Booster requests only the minimum set of Android system permissions strictly necessary to execute its latency optimization and diagnostic features:

4. Local Data Storage & Sandboxing

All user preferences (e.g., custom DNS server selections, game library assignments, floating HUD position, diagnostic history) are stored exclusively within Android's private, encrypted internal sandbox:

  • Room SQLite Database & DataStore: All diagnostic run logs and settings are stored locally on your device.
  • No Cloud Accounts: You do not need to register with an email address, username, or phone number to access Ping Booster.
  • Data Deletion: You can wipe all diagnostic history and reset preferences at any time using the in-app reset options or by clearing application data in Android System Settings.

5. Anonymous Telemetry & Crash Diagnostics

To identify rare device-specific hardware crashes, network interface drops, and optimize app performance across Android OEMs, Ping Booster incorporates an optional, privacy-centric telemetry pipeline:

  • Data Captured (If Enabled): Anonymized stack traces, device model (e.g., Samsung Galaxy S23), Android OS version, and aggregated feature invocation counters.
  • Zero Identifiable Data: We NEVER collect IP addresses, device identifiers (IMEI/MAC), personal files, or game titles played.
  • Opt-Out Guarantee: You can completely disable all telemetry at any time by toggling "Telemetry & Crash Diagnostics" to OFF in the Settings screen.
